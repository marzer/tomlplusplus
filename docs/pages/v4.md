@page v4 Possible breaking changes for v4
@tableofcontents

Each change on this page would improve toml++, but would also break something that users rely on today. They wait for
the next major version, and none of them is decided.

<!-- --------------------------------------------------------------------------------------------------------------- -->

@section v4-library Library

<!-- --------------------------------------------------------------------------------------------------------------- -->

@subsection v4-library-path-subpath Static path::subpath() overload

`toml::path::subpath(const_iterator, const_iterator)` doesn't use the path it's called on, so it could be a static member
function ([#310](https://github.com/marzer/tomlplusplus/pull/310)). Calls through an object would still compile.

The exported symbol would change from a const member function to a static one, so programs linked against a shared build
of toml++ would need rebuilding.

<!-- --------------------------------------------------------------------------------------------------------------- -->

@section v4-cmake CMake

<!-- --------------------------------------------------------------------------------------------------------------- -->

@subsection v4-cmake-minimum Minimum CMake version

The minimum is CMake 3.14. Raising it to 3.21 would let `project()` set `PROJECT_IS_TOP_LEVEL`, so
`cmake/project-is-top-level.cmake` could go. Copying runtime DLLs next to the Windows test executables would also stop
needing a version check.

It would break anyone building with CMake 3.14 to 3.20, which includes the 3.16 that Ubuntu 20.04 ships.

<!-- --------------------------------------------------------------------------------------------------------------- -->

@subsection v4-cmake-options Option names

The options use three naming styles. Most have a lowercase prefix, like `tomlplusplus_INSTALL`, `tomlplusplus_BUILD_LIB`
and `tomlplusplus_INSTALL_CMAKEDIR`. `TOMLPLUSPLUS_BUILD_MODULES` is all uppercase, and `BUILD_EXAMPLES` and
`BUILD_FUZZER` have no prefix. CMake convention is all uppercase, so every option would become `TOMLPLUSPLUS_*`.

Each renamed option breaks the scripts and recipes that set it, and one of them lives outside this repository. The
OSS-Fuzz builder image copies `fuzzing/build.sh` from master, and CIFuzz runs master's copy against every pull request.
`BUILD_FUZZER` has to keep working until master's script stops using it.

<!-- --------------------------------------------------------------------------------------------------------------- -->

@subsection v4-cmake-package-location Package files for header-only installs

A header-only install puts the CMake package files in `lib/cmake/tomlplusplus`. They are the same on every architecture,
so `share/cmake/tomlplusplus` suits them better, and Meson already uses it for header-only installs.

`find_package()` searches both locations. Anything that hard-codes the current path, such as a `tomlplusplus_DIR`
setting, would break.

<!-- --------------------------------------------------------------------------------------------------------------- -->

@subsection v4-cmake-cpack CPack

The top-level build includes CPack with no configuration, which adds a `package` target nobody has set up. Removing it
takes that target away from anyone who runs it.

<!-- --------------------------------------------------------------------------------------------------------------- -->

@section v4-meson Meson

<!-- --------------------------------------------------------------------------------------------------------------- -->

@subsection v4-meson-version-check Version check

The `tomlplusplusConfigVersion.cmake` that Meson installs accepts any newer version, so `find_package(tomlplusplus 2)`
finds 3.4. The one CMake installs only accepts the same major version, which matches the ABI namespace.

Making Meson's match would refuse version requests that succeed today.

<!-- --------------------------------------------------------------------------------------------------------------- -->

@subsection v4-meson-examples Installed examples

With `-Dbuild_examples=true`, Meson installs the example programs into `bin/`. They exist to show the API, and the CMake
build doesn't install them. Stopping it would remove files from installs that include them today.

<!-- --------------------------------------------------------------------------------------------------------------- -->

@subsection v4-meson-default-library Library type as a subproject

`meson.build` sets `default_library=shared` in its `default_options`. That is Meson's default anyway, so it only matters
when toml++ is a subproject. There it overrides the parent project's `default_library`, and with Meson older than 1.8 it
also overrides `-Ddefault_library` on the command line. Without it, the parent chooses.

Parent projects that build the library with `build_lib=true` and ask for static libraries would then get a static
toml++, where they get a shared one today.

<!-- --------------------------------------------------------------------------------------------------------------- -->

@section v4-repository Repository

<!-- --------------------------------------------------------------------------------------------------------------- -->

@subsection v4-repository-tipi Tipi.build

The `.tipi/` directory and the Tipi.build instructions in the README and on the main page support a package manager the
project doesn't test against. Removing them would break Tipi users.
